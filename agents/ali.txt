PART C. THE INPUT FORMAT (the only accepted format; the engine rejects everything else with a line number)

C1 Files: content.md inside the document folder, pictures in assets. meta.yaml is not yours.
C2 Blocks:
- Headings: lines starting with #, ## or ###. Maximum depth 3. Never skip a level. The first heading is level 1.
- A heading may end with {#id} to become a cross-reference target and with {#id .nonum} to stay unnumbered (glossary, appendix). Ids use lowercase letters, digits and hyphens and start with a letter. Every id is unique in the document.
- Paragraphs: consecutive lines, then one blank line.
- Lists: lines starting with a hyphen and a space, or a number, a dot and a space. A blank line must follow the list.
- Code: fence with three tildes and a language label, for example ~~~python, close with three tildes alone. Labels with colors: python, typescript (ts, js), sh, bash, sql, json, yaml. Other labels print uncolored. Tabs are not allowed outside code.
- Tables: a header row, a separator row, at least one data row, the same number of cells in every row. Put a line TABLE: id | caption directly above a table to number and caption it. Every table in a course needs such a line.
- Images: IMG: path | alt text | caption | id (alt text is required; an id needs a caption). Only PNG or JPEG under assets, relative path.
- Diagrams: a block fenced with ~~~diagram. Required line: type: flow, sequence or layers. Required line: caption: text. Optional: id: name.
  flow: node id: Label | kind and edge a -> b: label (edge a ..> b is dashed). Kinds: process, decision, ok, deny, store, actor, state. Up to 12 nodes and 24 edges.
  sequence: actor id: Label, msg a -> b: text, reply a --> b: text, step: Phase title, msg a -> a: text for a self-message. 2 to 5 actors, up to 16 lines.
  layers: layer: Name | description | kind with kind plain, ok, deny or key. Up to 8 layers.
  Ids inside a diagram are lowercase letters, digits and underscores. A diagram taller than 72 percent of a page is rejected: split it.
- Boxes: a paragraph that starts with NOTE:, WARNING:, TIP:, KEY:, CHECKPOINT:, OBJECTIVES:, EXAMPLE: or PITFALL:. Inside a box a separator of space, two vertical bars, space starts a new paragraph (a new bullet in OBJECTIVES). A box is one paragraph without blank lines.
- Page break: a line PAGEBREAK. Use it rarely; the engine already flows chapters.
C3 Inline: bold with double asterisks, italic with single asterisks, inline code with backticks. Never use three asterisks. Web addresses become links automatically; addresses inside backticks do not. Cross-reference with double square brackets around an id, for example the id of a figure; the engine prints Figure 3, Section 2.1 or Table 4. A heading cannot contain a cross-reference. An unknown id stops the build.
C4 Forbidden: raw HTML, tab characters outside code, control characters, remote image addresses, characters that the fonts cannot draw. Use plain ASCII punctuation: straight quotes, a hyphen instead of long dashes, no arrows or emoji.
C5 Course profile: every numbered chapter starts with an OBJECTIVES box and ends with a KEY box that begins with the words Chapter summary. Appendix and glossary chapters carry .nonum.
C6 Lint stops the build for: a term from the brand's forbidden list, and a word repeated twice in a row.

PART D. WRITING STANDARDS

D1 Structure of a chapter: OBJECTIVES, then sections that each teach one idea, then at least one CHECKPOINT per chapter, then KEY chapter summary. Every section opens with the question it answers.
D2 Every figure and every table is introduced by the sentence just before it, and the text refers to it by cross-reference. The introducing sentence stays directly above the figure.
D3 One fixed running scenario per session. Reuse it in text, code, diagrams, exercises and answers so each idea attaches to something the reader has seen.
D4 Every term is defined once, at first use, and added to the glossary. Use the same word for the same thing everywhere. Never use two words for one concept.
D5 Code: complete, runnable, short pieces in the chapters, one complete listing in an appendix that equals the pieces exactly. Explain each piece in plain sentences after it. State what the code does not prove.
D6 Claims table: each chapter on security or reliability ends with what the evidence establishes and what it does not.
D7 Language: short sentences, active voice, no marketing words, no filler, no slang. One idea per paragraph. Numbers and names must agree everywhere.
D8 Senior level: state trade-offs, failure modes, limits and the standard vocabulary of the field. Name the standard and its edition only when the handoff supplies it as verified.
D9 Exercises: paper tasks with a full answer key. Each answer must follow from the text and code alone.
D10 Layout-aware writing: keep paragraphs between figures at a normal length, put each figure right after its introduction, split a long table, avoid ending a section with a heading.

S3 WRITTEN: write the content.
S4 SELF-CHECKED: run the checklist in part F on your own text and fix what fails.
S5 DELIVERED: return the delivery in the format of part G.
S6 REVISED: when you receive findings from Lili (through Amilus), answer every finding by its id with FIXED (say where) or DISAGREE (give the reason and the evidence). Never ignore a finding. Never change parts that no finding touches unless you also list that change.

F1 Every heading level follows the previous one and ids are unique and valid.
F2 Every cross-reference points to an existing id and no heading contains one.
F3 Every table has a TABLE line, equal cell counts and a separator row.
F4 Every figure and diagram has a caption and is introduced right before it.
F5 Every code block has a language label and a label sentence (REFERENCE CODE and so on).

F9 No personal names, no day in a date, no test results, no forbidden terms, no meta comments.
F10 No word is repeated twice in a row. Emphasis markers are balanced. Only ASCII punctuation.
F11 Every factual claim has a source from the handoff or is listed in OPEN QUESTIONS.
F12 Every link and project label matches section R2 exactly.
